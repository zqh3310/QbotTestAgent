## 3. 产品定位

QBot 是公司内部的内嵌 Agent 工作台，第一版目标不是给 AI 技术人员配置底层模型和 agent，而是让产品、运营、领导等非技术用户可以用简单入口完成日常工作任务。

核心产品心智：

| 概念 | 用户怎么理解 | 第一版要求 |
|---|---|---|
| 新建任务 | 开始一次新的工作请求 | 第一优先级，必须稳定、简单、可连续多轮使用 |
| 任务 | 历史会话/工作记录 | 必须可打开、可搜索、可恢复 |
| 空间/工作区 | 本地工作目录或任务上下文 | 必须让用户能选择默认工作区或本地文件夹，不要求用户理解 `cwd` |
| 专家 | 选择一个容易理解的角色来帮我做事 | 必须比“模型/agent”更好懂；专家选择、召唤、创建要可测 |
| 技能 | 做某类事的方法/能力包 | 用户看到的是“安装/更新/删除/历史”，不需要理解 runtime projection |
| 连接器 | 连接外部应用、数据源、工具 | 用户不需要理解 MCP，只看到“平台可用/我的连接器/内置能力”等分组 |
| 知识 | 管理任务时怎么使用公司/个人知识 | 第一版配置层和成果库要清楚，运行时应用层 #154 仍阻塞 |
| 成果 | 任务产出的文件和资料 | 当前任务右侧成果区 + 跨会话任务成果库都要覆盖 |

## 5. 详细产品功能说明

### 5.1 登录、身份与账户

来源：#15, #29  
入口：启动 QBot 后的登录页、左下用户入口、退出按钮  
源码：`src/App.tsx`, `src/Sidebar.tsx`, `server/auth.mjs`, `server/index.mjs`

最终效果：

- 未登录时展示登录页，主按钮文案为 `使用 Lingxi 登录` 或当前 provider label。
- 用户点击登录后通过浏览器完成 OAuth2 授权，回到 QBot 工作台。
- 登录后左下用户区展示真实用户信息，优先展示姓名/domainAccount，辅助信息展示部门、邮箱或 provider。
- 退出后回到登录页，工作台数据不可继续访问。
- 重启 QBot 后应能通过 refresh token 恢复同一用户态；过期或撤销时回到重新登录入口。
- HTTP API 和 WS 都应基于 app session token 鉴权，不能接受裸 `uid`、`local-user` 或 `x-user-id` 作为正式身份。

关键状态：

- 正常登录：进入工作台，任务、空间、个人设置可用。
- 登录中：按钮显示 `登录中…`，避免重复触发。
- 登录失败：登录页显示错误提示和重试入口。
- 会话过期：重新登录，不保留可访问的旧工作台状态。
- 退出中：退出按钮显示 `退出中…`。

测试关注：

- 真实 Lingxi 登录、取消授权、网络中断、token 过期、退出再登录、重启恢复。
- 非技术用户视角：登录页只需要一个清晰动作，不要求知道 OAuth2。

### 5.2 工作台壳层、任务与空间

来源：#140, #141, #143  
入口：左侧栏 `新建任务`、`任务`、`空间`、搜索、收起/展开  
源码：`src/Sidebar.tsx`, `src/runtime.tsx`, `src/ComposerExtras.tsx`

最终效果：

- 左侧第一个主入口是 `新建任务`，点击进入空白任务草稿。
- 任务列表展示历史任务数量和标题，点击可恢复对应任务。
- 顶部搜索按钮打开任务搜索弹层，显示匹配数量和任务列表。
- 左侧栏可收起，收起后可通过展开按钮恢复。
- `任务` 和 `空间`分组可折叠；空间中聚合项目和本地工作空间下的任务。
- 术语应保持用户可理解：尽量使用“任务/空间/工作区”，不要让普通用户理解 session、cwd、runtime 之类内部词。

关键状态：

- 无任务：显示 `还没有任务`。
- 搜索无结果：显示 `没有匹配的任务`。
- 无空间：显示 `还没有空间 —— 发起任务时在打字框下选工作空间`。
- 草稿态：点新建任务不应立即污染任务列表，用户发送第一条消息后才真正形成任务。

已发现差异：

- #170 写明支持任务 hover 删除，但当前最新源码静态检查未在 `Sidebar.tsx` 发现删除按钮，也未搜到删除会话接口。该需求不能按“已完成可测”写入第一版通过标准，需开发确认：要么补实现，要么从第一版范围剔除。

### 5.3 新建任务与聊天

来源：#140, #164, #177, #180, #193  
入口：`新建任务` 页面中间聊天区  
源码：`src/components/assistant-ui/thread.tsx`, `src/runtime.tsx`

最终效果：

- 空任务展示欢迎语、场景分类和预设 prompt。
- 输入框 placeholder 为 `输入消息…`，用户可输入中文自然语言任务。
- 发送后用户消息和 QBot 回复都在左侧主阅读流中展示，角色区分靠样式而不是左右分栏跳动。
- 运行中顶部状态条展示 `思考中/生成中/执行中`、耗时和 token。
- 运行中发送按钮变成停止按钮，可中断生成。
- 完成后顶部展示耗时和 token。
- 回复下方提供复制、重新生成、更多菜单、导出 Markdown。
- 支持附件上传，图片/文本附件可预览和随消息发送。
- 支持快速反馈按钮，把当前上下文、草稿、附件、截图等证据整理后作为反馈任务交给 agent。
- 支持提示词美化按钮，但没有输入或正在处理时不可重复触发。

关键状态：

- 空输入不发送。
- 纯附件可发送。
- 长文本输入不应卡死、不应遮挡工具条。
- 多轮对话应保留上下文，不应每轮误建新任务。
- 运行中切换页面/返回后不应出现不可恢复状态。

非技术用户体验要求：

- 用户不需要选择底层 agent 才能开始。
- 默认设置必须能跑通普通任务。
- 工具条应辅助而不是阻塞，任何专业概念都应有清晰中文解释或默认值。

### 5.4 场景、预设 Prompt、工作区与引用

来源：#141, #143  
入口：新建任务欢迎区、输入框上方和下方  
源码：`src/ComposerExtras.tsx`, `server/scenes.mjs`

最终效果：

- 欢迎区展示场景大类，如 `日常办公`、`代码开发`、`设计创意`。
- 选择场景后，输入框上方出现该场景的预设 prompt 按钮，点击可填入完整提示词。
- 输入框内出现场景标签，可一键移除。
- 输入框下方展示工作区选择：默认 `默认工作区`，可打开本地工作空间。
- 工作区选择弹层支持搜索历史工作空间，选择后当前草稿任务绑定该工作区。
- 输入 `@` 时弹出工作区文件引用；输入 `/` 时弹出技能/命令候选。

边界：

- 项目任务工作区由项目固定，第一版项目入口不验收，因此本轮重点验证个人任务工作区。
- 如果当前工作区无文件，`@` 引用应提示空状态，不应报错。

### 5.5 专家

来源：#124, #126, #128, #130, #197  
入口：左侧 `专家`，以及输入框工具条第一个专家/工作模式按钮  
源码：`src/ExpertsView.tsx`, `src/ComposerTools.tsx`, `server/index.mjs`, `server/engine.mjs`

最终效果：

- `专家` 页默认进入专家 tab。
- 页面分区包括：`为您推荐`、`最近召唤`、`我的专家`、`专家市场`。
- `为您推荐` 中有 `通用助手`，并展示当前使用中状态。
- 专家卡片展示头像/emoji、名称、摘要、擅长领域、作者/部门。
- 点击专家卡片打开详情弹窗，展示能力介绍、擅长领域、示例问题，并可点击 `召唤`。
- 召唤专家后回到新建任务页，新任务应以该专家角色运行。
- 最近召唤可展示并允许移除。
- 我的专家展示用户自己创建的私有专家。
- 创建专家入口优先引导“用对话创建”，召唤 `专家构建师`；备用路径是手动填表。
- 对话创建专家后，专家必须出现在 `我的专家`，可再次召唤。#197 明确修过“创建后不可见”的问题，这是重点回归点。

输入框专家/工作模式：

- 默认显示 `Craft`，表示主动动手完成任务。
- 可切换 `Ask`：只回答/沟通，不动手改文件。
- 可切换 `Plan`：先出方案再执行，只读规划。
- 可从最近召唤专家中快速切换。
- 如果没有最近专家，显示 `去专家市场召唤`。

测试关注：

- 专家选择后，第一轮和后续多轮都保持该角色。
- 在一个任务中切换专家，用户应能理解当前到底是谁在工作。
- 创建专家长流程要可完成，不能只回复“已创建”但页面不可见。

### 5.6 技能

来源：#31, #69, #132, #135, #137, #209  
入口：`专家` 页中的 `技能` tab，以及输入框工具条 `技能`  
源码：`src/ExpertsView.tsx`, `src/ComposerTools.tsx`, `server/skill-install.mjs`

最终效果：

- 技能页包含 `已安装`、`技能市场`、`历史` 三个子 tab。
- 已安装技能展示名称、版本、来源、安装/更新时间、是否已缓存。
- 已安装技能可更新、删除；有历史版本时可回退。
- 技能市场支持搜索，展示中文名/英文名、描述、分类、最新版本、下载数、stars/rating、来源标签。
- 未安装技能可点击安装；已安装技能显示更新/删除。
- 历史 tab 展示最近安装、更新、回退、删除记录。
- 输入框工具条 `技能` 可搜索已安装技能；不选代表自动；选中后输入框内显示技能 chip，可移除。
- `导入技能` 会跳转到技能市场。

已知风险：

- #209 当前仍 opened/status in-progress：真实 SkillHub `/download` 可能直接返回 ZIP 二进制，当前 main 上有风险把 ZIP 当 JSON 解析导致安装失败。第一版若依赖真实 SkillHub 安装，必须在开发交付前确认 #209 修复已合入并回归通过。

测试关注：

- fixture/mock 市场和真实 SkillHub 市场要分开验收，不能用 mock 通过冒充真实通过。
- 安装失败错误要可理解，不能暴露 token、cookie、presigned URL、二进制内容或 server-only ref。
- 技能与专家绑定时，召唤专家应能自动准备其依赖技能；失败不能阻塞用户理解。

### 5.7 连接器

来源：#64, #67, #163, #165, #166, #167, #168, #195, #200  
入口：左侧 `连接器`，输入框工具条 `连应用`  
源码：`src/ConnectorsView.tsx`, `src/connectorUiCopy.ts`, `src/ComposerTools.tsx`

最终效果：

- 连接器页标题为 `连接器`，右上角有 `添加连接器`。
- 页面说明使用普通用户语言：外部应用、数据源和工具，不要求用户理解 MCP。
- 连接器按来源分组：
  - `我的连接器`：自己添加维护，只在个人配置生效。
  - `平台可用`：平台提供的外部应用和数据源。
  - `项目提供`：仅项目/工作区上下文生效，本轮项目入口不深测。
  - `内置能力`：随 QBot 提供。
  - `桥接能力`：宿主或会话桥接。
  - `其他连接器`。
- 卡片展示名称、状态、描述、工具/数据源/提示模板数量、默认自动/手动使用等信息。
- 可添加自定义连接器，字段包括连接器名、显示名、启动命令、启动参数、工具名。
- 连接器名和启动命令必填；名称只能使用英文/数字/下划线/中划线。
- 可删除自己添加的连接器，删除前确认；内置连接器不能删除。
- 输入框 `连应用` 默认自动使用可用连接器；显式选择后本轮只使用选中的连接器；可切回自动。

关键状态：

- 平台连接器目录未配置：提示 `平台连接器目录暂未启用`，但已安装、个人添加和项目提供连接器仍可用。
- 未登录：提示登录后可查看平台授权状态。
- 平台错误：提示暂不可用，不影响已安装/项目提供连接器。
- 专家绑定连接器不可用：工具条提示 `需处理`。

测试关注：

- #195 曾出现 MCPHub 多服务配置但 QBot 只显示内置 SQL 的问题；必须验证平台可用连接器展示。
- #200 是真实 MCPHub 验收 lane，真实平台数量和状态要与 MCPHub 控制面可见结果一致，允许用户授权过滤。

### 5.10 个人设置、模型与运行方式

来源：#30, #65, #120, #140, #155, #156, #157, #158, #161  
入口：左下用户菜单 `个人设置`  
源码：`src/AssistantConfig.tsx`, `connection-view.mjs`

最终效果：

个人设置包含：

- 界面主题：跟随系统、浅色、深色；主题风格下拉。
- 角色人设：项目外默认口吻和工作方式，可用推荐人设填充。
- 用户画像：称呼、背景、偏好，始终生效。
- 默认执行方式：Claude Code / Codex runtime family 等可用执行方式。
- 模型绑定：展示当前使用、来源、平台连接状态、个人连接状态和可选模型。
- 个人自定义 LLM：连接标识、显示名称、协议、接入地址、模型名、密钥、保存/删除。
- 管理员运营开关：任务体验评估，只有 admin 可见。
- 底部保存按钮，未保存时提示 `有未保存的修改`。

重要产品原则：

- 非技术用户默认不应该为了开始任务而必须选模型或 agent。
- 模型/运行方式属于个人设置和高级切换；聊天区的模型快捷选择必须展示可理解的连接名和安全档位。
- UI 只能看到 redacted 连接状态，不能回显密钥。
- 保存个人连接不应静默覆盖平台默认，必须显式选择才生效。
- session model override 要跟随多轮 resume，不应导致会话断裂。

测试关注：

- 密钥输入后保存，重新打开只能看到 redacted 状态。
- 删除个人连接后不可继续选中。
- 选择不可用模型时按钮禁用并展示原因。
- 切换默认执行方式后，新建任务默认值变更；已有任务按会话设置恢复。
- 安全档位 M1-M4 当前第一版以展示为主，不做强 enforcement，来源 #120。

## 7. 测试设计原则

后续测试用例应遵循：

1. 功能测试和 Codex 自动化测试的场景应一一对应，只是表达形式不同。
2. 用户版用例要让普通测试同事按步骤执行；Codex 版要让 Codex 像人一样操作 UI、截图、记录完整提问和完整回复。
3. 自动化不是 shell/API 底层测试，重点是模拟用户点击、输入、等待 agent 回复、切换页面、收集证据。
4. 用例要拆成原子场景和完整流程场景：一个原子场景是一条 testcase，一个完整业务流程也是一条 testcase，不能把很多验证点塞成一条超长用例。
5. 优先级排序从 P0 开始。正向高频路径优先；低概率异常场景可以是 P2/P3。
6. 使用等价类、边界值、状态迁移、异常注入、长文本、多附件、多轮会话、重复点击、网络失败、权限失败、重启恢复等方法。
7. 每个用例必须标 issue 来源；如果是源码暴露但 issue 不明确，标 `源码入口`。
8. 每个自动化用例必须要求截图和证据：入口截图、关键操作截图、用户提问全文、agent 回复全文、断言结果、失败原因。

## 8. 推荐第一版 P0 端到端流程

这些流程不是替代原子用例，而是完整用户场景：

| 流程 | 目标 | 覆盖功能 |
|---|---|---|
| 登录后完成一个普通办公任务 | 非技术用户首次使用是否顺畅 | 登录、新建任务、发送、等待回复、任务列表、退出恢复 |
| 切换产品经理专家完成需求设计 | 验证专家角色是否简单有效 | 专家市场、召唤专家、多轮对话、成果输出 |
| 安装技能后在任务中显式选择技能 | 验证技能市场和任务工具条 | 技能搜索、安装、输入框 chip、回复质量 |
| 使用连接器完成外部数据查询任务 | 验证连接器可理解性和路由 | 连接器页、连应用、状态提示、异常连接器 |
| 配置知识源并查看任务成果库 | 验证知识页和成果闭环 | 知识源、知识引擎、成果库、来源任务 |
| 长文本 + 多附件 + 快速反馈 | 验证复杂输入与证据链 | 附件、长文本、反馈、截图、agent 追问 |
| 设置个人画像和默认执行方式后重启 | 验证个人配置持久化 | 个人设置、保存、重启、默认值恢复 |

## 9. Agent Team 持续工作机制

因为 issue 会持续更新，agent team 应按“最新源码 + 最新 issue 正文快照 + 输出口径固定”的方式工作。

推荐机制：

| 角色 | 职责 | 触发时机 | 产物 |
|---|---|---|---|
| Issue 监控/情报 agent | 拉取 GitLab issue、正文、标签、状态、MR 线索，生成 diff | 每天/每次开发批量更新后/用户手动要求 | issue 快照、变更摘要 |
| 产品功能分析 agent | 从 feature/enhancement/design/bug 正文抽取用户可见能力和非目标 | issue 快照更新后 | 功能来源表、PRD 变更建议 |
| 源码入口审计 agent | 从最新 main 扫描前端入口、data-testid、按钮、路由 | 每次代码更新后 | 前端入口核对表 |
| 测试用例设计 agent | 基于 PRD 和源码生成原子场景 + 完整流程场景 | 功能范围稳定后 | 功能测试用例、Codex 自动化用例 |
| 测试用例评审 agent | 专职挑刺，检查颗粒度、步骤、预期、优先级、issue 来源、异常覆盖 | 每次用例生成后 | 评审意见、阻断问题 |
| 自动化执行 agent | 像真实用户操作 QBot，截图并记录提问/回复/断言 | 开发交付测试后 | 自动化执行证据包 |
| 证据质量 agent | 检查截图、日志、回复全文、评分是否完整可信 | 自动化执行后 | 证据质量报告 |

关键规则：

- 每份产物必须写清楚代码 commit、issue 快照时间、Milestone issue 数量和筛选口径。
- 不允许沿用旧产物的统计数字；重新生成必须从最新 source 重新统计。
- 不允许只看 issue 标题；必须读取正文。
- 不允许把 bug issue 机械生成大量功能用例；只有正文包含明确用户功能或回归点时才转测试场景。
- 不允许把项目/自动化纳入第一版完整验收，除非用户更新范围。
