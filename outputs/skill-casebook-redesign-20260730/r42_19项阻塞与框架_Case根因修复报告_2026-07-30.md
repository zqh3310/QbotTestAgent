# r42 19 项阻塞与框架 / Case 根因修复报告

## 结论

上一轮被归入 `trusted_blocked=17`、`framework_issue=1`、`testcase_issue=1` 的 19 项，并不是 19 个独立的产品故障。

- 17 个 blocked 收敛为 3 条能力链：Skill、专家、MCP。
- Skill 的 9 项中，只有 `BETA-SKILL-001` 是直接根因；其余 8 项是前置能力未建立后的链式阻塞。
- MCP 的 6 项中，只有 `BETA-MCP-002` 是直接根因；其余 5 项是连接器选择前置失败后的链式传播。
- 专家的 2 项分别由 Skill 前置传播、脏环境/专家创建链路不完整造成。
- `BETA-FILE-005` 是 QA 框架附件白名单与产品发布契约不一致。
- testcase 问题是把“全量重初始化”错误等价成“Skill 安装账本清空”，并使用了产品中不存在的 Skill 操作入口。

这些问题都可以通过技术手段修复。框架和 Casebook 已完成对应修改，但修复后的产品结论必须通过新一轮真实执行确认，不能把静态修复直接记为 `trusted_pass`。

## 框架修改

### Skill

- 技能市场数据源改为 `window.agent.getSkillsCatalog()` 的 `market` 分支。
- 目录 identity 与可见 `.skill-name` 卡片匹配，不再把“已安装 2 个”解释为“市场只有 2 个”。
- 使用固定 seed、稳定 identity、可见安装按钮抽样 10 个。
- 10 个 Skill 串行安装并逐项记录安装回执，避免并发安装互相污染。
- 只清理 QA 受管账本中记录的 Skill，绝不清理用户已有 Skill。
- 从真实已安装 Skill 的 identity、描述、README 生成任务，不再用与 Skill 无关的固定 prompt。
- Skill 选择走 Composer 公开入口；同时校验 UI chip、`selectedSkills` 和 task-bound execution event。

### 专家

- 创建前精确清理 `QBot内测研究/数据/交付专家-*`，不触碰非 QA 专家。
- 专家列表 readback 同时合并可见卡片、公开目录和 capabilities。
- 修正“名称 + 私有状态”误拼接及空 ID 被字符串化成 `"null"` 的问题。
- 创建、删除都更新 QA 受管资源账本。

### MCP

- 手动连接器模式的硬条件改为：
  1. 手动选择列表可见；
  2. 存在可选服务；
  3. `connectorRouting.mode === "manual"` 或公开控件明确选中；
  4. 选择后 `selectedConnectors` 精确一致；
  5. Composer 显示聚合连接器 chip。
- 不再把易变文案作为通过/失败条件。

### 附件

- QA 附件桥补充 `.log` 支持，与产品发布契约保持一致。
- 新增独立测试，防止后续再次漏掉产品已支持的附件类型。

## Casebook 修改

新版 Casebook 共 51 条，其中 Skill 12 条，明确拆分：

- 市场目录与安装链：进入技能市场、稳定抽样 10 个、分两组安装、readiness、已安装/历史/Composer 多视图核对。
- 已安装 Skill 使用链：从 Composer 精确选择 5 个 Skill，按真实 Skill README 派生任务，执行两轮会话，验证回复与 task-bound Skill 事件。
- 清理链：只卸载 QA 本轮安装项，验证市场、已安装、历史、Composer 状态一致。
- 专家创建前增加 QA 残留专家精确清理。
- MCP 改用公开 routing/selectedConnectors/chip 契约。
- 初始化用例不再要求全量重初始化清空 Skill 安装账本。

## 剩余风险

- 这次修复消除了已知的框架误判、脏环境传播和 Case 入口错误。
- 是否存在真实 Skill 市场安装失败、专家容量/创建问题、MCP 调用失败，仍必须由干净 UAT 新轮真实操作判定。
- 新轮必须从第一条开始使用新的 51 条 Casebook，不得继承上一轮 Skill/专家/MCP 的失败结论。
- 若新的直接根 Case 失败，后续依赖 Case 应标记为明确的 `upstream_capability_prerequisite`，但报告聚合时只计算一个根因，避免把链式传播重复计为多个产品问题。
